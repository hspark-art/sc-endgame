**대회 상세 페이지**가 ASL 을 보는 주 동선입니다. 대회 탭에서 줄을 펼쳐
"대회 상세 보기"를 누르거나, 선수 페이지의 대회명을 누르면 갑니다.
진출 현황은 우승 → 준우승 → 4강 → 8강 → … 순으로, 누가 어디까지 올라갔는지
한눈에 보여 줍니다.

경기 기록 탭은 1,299매치를 한 번에 늘어놓지 않고 **최신 대회부터** 보여 줍니다.
대회 칩을 직접 고르면 그 선택을 유지합니다.

끝장전에도 기록이 있는 선수는 상세 페이지에서 서로 오갈 수 있습니다.

## CG 제작 툴 (관리자 전용)

`admin/` — 1920×1080 대진표 이미지를 만들어 PNG 로 내려받습니다.
**관리자만 들어갈 수 있습니다.**

### 로그인

서버(PHP)가 세션으로 판단합니다. 자바스크립트로 비밀번호를 확인하는 방식은
소스 보기 한 번이면 뚫리므로 쓰지 않았습니다.

```
admin/index.php   로그인 · 최초 계정 만들기
admin/cg.php      CG 툴 (로그인해야 열립니다)
admin/logout.php  로그아웃
admin/auth.php    인증 로직
admin/config.php  ← 계정 정보. 저장소에 없습니다 (.gitignore)
```

**처음 올린 뒤 `admin/` 에 접속하면 아이디·비밀번호를 정하는 화면이 뜹니다.**
정하고 나면 `admin/config.php` 가 서버에 만들어지고(권한 600), 그 뒤로는
로그인 화면만 나옵니다. **올리자마자 바로 계정을 만들어 두세요** — 그 전에는
누구나 계정을 선점할 수 있습니다.

비밀번호는 bcrypt 해시로만 저장하고 평문은 어디에도 남기지 않습니다.
CSRF 토큰, 세션 고정 방어(로그인 시 세션 재발급), 10분에 8번 실패 시 잠금이
들어 있습니다. 잠금은 세션 기준이라 쿠키를 지우면 초기화되지만, bcrypt 검증
자체가 느려서(회당 0.2~0.4초) 무차별 대입은 현실적으로 어렵습니다.

계정을 잊었으면 FTP 로 `admin/config.php` 를 지우면 최초 설정 화면이 다시 뜹니다.

`.htaccess` 로 `config.php`·`auth.php` 직접 열기와 폴더 목록 보기를 막아 뒀습니다.

PHP 가 도는 곳에서만 동작합니다 — 카페24는 되고, GitHub Pages 는 PHP 를
실행하지 않아 안 됩니다 (백업용이라 문제되지 않습니다).

### 도구 기능

1920×1080 캔버스에 직접 그립니다.
캔버스에 직접 그리기 때문에 바깥 라이브러리가 필요 없고, 미리보기와 내려받은
PNG 가 정확히 같습니다.

- **선수 사진 업로드** — 파일 선택, 또는 미리보기에 끌어다 놓기.
  올린 뒤에는 **끌어서 위치**를 잡고 **휠로 크기**를 맞춥니다.
- 선수 이름은 끝장전·ASL 기록실 선수 95명에서 자동완성되고, 고르면 종족이 따라옵니다.
- 스폰서 로고·방송국 로고도 올릴 수 있고, 좌우 배경색과 타이틀 색을 바꿉니다.
- 상자 세 개(경기 방식·상금·사용맵)는 제목과 내용을 자유롭게 고칩니다.
  내용 줄 문법: `[글자]` 는 노란 테두리 강조, `* 글자` 는 작은 회색 주석, 빈 줄은 한 칸 띄우기.
  상자 높이는 내용에 맞춰 알아서 늘어납니다.
- 입력한 내용은 사진까지 이 브라우저에 자동 저장됩니다. 다른 컴퓨터로 옮기려면
  "설정 내보내기"로 JSON 을 저장했다가 "설정 불러오기" 하세요.
- 사진은 브라우저 안에서만 처리되고 어디에도 올라가지 않습니다.

## ASL 데이터 갱신하기

시즌이 진행되면 시트에 경기가 쌓입니다. 반영 순서는 이렇습니다.

```bash
python3 tools/asl_import.py <새 ASL.xlsx> --diff   # 1) 뭐가 달라지는지 먼저 보기
python3 tools/asl_import.py <새 ASL.xlsx>          # 2) 괜찮으면 반영
python3 tools/build.py                             # 3) 사이트 다시 만들기
python3 tools/deploy.py                            # 4) 올리기
```

`--diff` 는 **저장하지 않고** 지금 데이터와 무엇이 다른지만 보여 줍니다.

```
세트 2177 → 2181 (+4) · 매치 1299 → 1303 (+4)
새 선수: 신예선수
+ ASL Season 22 — 24강 경기 추가 (5 → 7세트)
+ ASL Season 22 — 16강 새 라운드 (0 → 2세트)
```

`+` 는 대회가 진행되면서 자연스럽게 늘어난 것이고, `!` 는 **기록이 줄거나
사라진 것**이라 시트에서 줄이 지워졌을 수 있다는 뜻입니다.

```
! ASL Season 21 — 8강 세트가 줄었음 (16 → 15세트)
! 기록이 줄거나 사라졌습니다. 시트에서 지워진 줄이 없는지 확인하세요.
```

시트에 종족이 엇갈리게 적힌 선수가 있으면 최빈 종족으로 맞추고 무엇을
바꿨는지 알려 줍니다 (원본 엑셀은 건드리지 않습니다).

## 앞으로 ASL 데이터를 어디서 가져올까

| 방법 | 정확도 | 드는 손 | 지금 |
| --- | --- | --- | --- |
| **지금처럼 시트에 직접 기록** | 가장 높음 | 매주 입력 | 동작 중 |
| Liquipedia 에서 자동 수집 | 높지만 검수 필요 | 초기 개발 + 표기 맞추기 | 미구현 |
| 사이트에서 바로 입력 (admin) | 가장 높음 | 입력이 편해짐 | 미구현 |

**당분간은 시트를 그대로 쓰는 편이 낫습니다.** 22시즌치가 이미 한 형식으로
쌓여 있고, 위 `--diff` 로 안전하게 반영되기 때문입니다.

Liquipedia 는 ASL 결과가 방송 당일 정리되고 pubg-meta 도 이미 출처로 쓰고
있어 후보로 좋습니다. 다만 위키라 **표기가 흔들립니다** — 선수명이 한글/영문
/아이디로 섞이고 맵 이름도 판마다 달라서, 우리 시트 표기와 맞추는 대응표를
계속 손봐야 합니다. 검수 없이 자동 반영하면 틀린 기록이 그대로 사이트에
올라갑니다. 그래서 쓰더라도 **"초안을 만들어 주고 사람이 확인"** 하는 식이
맞습니다. (참고: Liquipedia API 는 이용약관상 연락처가 담긴 User-Agent 와
출처 표기가 필요하고 호출 간격 제한이 있습니다.)

세 번째 방법은 이미 관리자 로그인이 있으니 자연스럽게 붙일 수 있습니다.
경기 하나를 폼으로 입력 → 서버에 쌓기 → 빌드. 시트를 아예 대신할 수도 있고
시트와 병행할 수도 있습니다. 필요해지면 만들면 됩니다.

## 사이트에 올리기 (자동 배포)

실제 사이트는 **카페24의 pubgin.com/endgame** 입니다. GitHub 은 백업이라
거기 올린다고 사이트가 바뀌지 않습니다.

```bash
python3 tools/build.py     # 만들고
python3 tools/deploy.py    # 올리고
```

`deploy.py` 는 **바뀐 파일만** 올립니다. 처음 한 번은 159개가 다 올라가고,
그다음부터는 실제로 달라진 것만 올라가서 몇 초면 끝납니다.

접속 정보는 둘 중 편한 쪽으로 넣습니다. **저장소에는 들어가지 않습니다.**

```bash
cp data/deploy.sample.json data/deploy.json   # 파일을 열어 비밀번호를 채우세요
```

또는 환경변수로:

```bash
export SC_FTP_HOST=pubgin.com
export SC_FTP_USER=pubgin
export SC_FTP_PASS=비밀번호
export SC_FTP_DIR=/www/endgame
```

옵션

| | |
| --- | --- |
| `--dry-run` | 올리지 않고 무엇이 올라갈지만 봅니다 |
| `--all` | 바뀐 것만이 아니라 전부 다시 올립니다 |
| `--no-tls` | 서버가 FTPS 를 못 받을 때 평문 FTP 로 |

**지우는 일은 하지 않습니다.** 올리고 덮어쓰기만 합니다. 서버에만 있는
파일(관리자 계정 `admin/config.php`, 로그 등)은 건드리지 않습니다.

FTPS(암호화)로 먼저 붙어 보고, 서버가 못 받으면 평문 FTP 로 내려갑니다.

## 다른 주소로 옮기기

이 사이트는 **어디에 올려도 그대로 동작합니다.** 지금처럼 하위 폴더
(`.../sc-endgame/`)에 두든, 새 도메인 루트에 통째로 올리든 같습니다.
내부 링크가 전부 자기 파일 기준 상대경로라서 그렇습니다 —
루트 절대경로(`/...`)도, `<base href>` 태그도, 하드코딩된 `sc-endgame/`
경로도 쓰지 않습니다. 빌드할 때마다 `tools/audit.py` 가 이걸 확인합니다.

주소를 바꿀 때 손볼 곳은 딱 하나, **`data/site.json` 의 `baseUrl`** 입니다.

```json
{
  "baseUrl": "https://새도메인.com",
  "cname": null
}
```

고치고 다시 빌드하면 끝입니다.

```bash
python3 tools/build.py
```

한 번만 시험해 보고 싶으면 설정을 건드리지 않고 인자로 넘겨도 됩니다.

```bash
python3 tools/build.py --base-url https://새도메인.com
```

`baseUrl` 이 들어가는 곳은 세 군데입니다 (전부 자동으로 따라 바뀝니다).

| 곳 | 왜 절대 주소가 필요한가 |
| --- | --- |
| `<link rel="canonical">` · `og:url` — 133개 페이지 | 검색엔진과 카톡 미리보기가 절대 주소를 요구합니다 |
| `sheets.html` 의 IMPORTDATA 수식 | 구글 시트가 바깥에서 가져오는 주소입니다 |
| `csv/index.json` 매니페스트 | 프로그램이 CSV 를 가져갈 때 쓰는 주소입니다 |

GitHub Pages 에 커스텀 도메인을 붙이는 거라면 `cname` 에 도메인을 적으세요.
`CNAME` 파일을 만들어 줍니다 (null 로 되돌리면 파일도 지웁니다).

```json
{ "baseUrl": "https://sc.example.com", "cname": "sc.example.com" }
```

옮긴 뒤에는 브라우저 개발자도구 콘솔에 404 가 없는지만 보면 됩니다.
CSS·JS 는 페이지마다 안에 박혀 있어서 따로 불러오지 않고, 바깥에서
가져오는 것은 폰트(jsDelivr)·중계진 로고·SOOP 방송 API·유튜브 iframe
뿐입니다. 캐시 때문에 옛날 화면이 보이면 주소 뒤에 `?v=숫자` 를 붙이세요.

## 다시보기 영상 붙이기

경기별 영상은 `data/videos.json` 의 `matches` 에 적습니다. 키는
`"경기날짜|선수A|선수B"` 이고 선수 이름은 가나다순입니다.

```json
"matches": {
  "2026-08-12|김지성|김택용": "https://www.youtube.com/watch?v=XXXXXXXXXXX"
}
```

유튜브에서 자동으로 찾아 채우려면 YouTube Data API v3 키가 필요합니다.

```bash
export YOUTUBE_API_KEY=...
python3 tools/fetch_videos.py            # 어떻게 매칭되는지 먼저 확인
python3 tools/fetch_videos.py --write    # data/videos.json 에 기록
python3 tools/build.py                   # 사이트에 반영
```

두 선수 이름과 경기 날짜가 제목에 함께 있으면 점수를 높게 매기고, 경기일보다
앞서 올라온 영상은 아예 후보에서 뺍니다. 손으로 적어 넣은 항목은 덮어쓰지
않습니다. 영상이 없는 경기는 사이트에서 두 선수 이름으로 채널을 검색하는
링크로 대신 안내합니다.

사이트 아래쪽 "데이터 내려받기" 에서 CSV 여섯 종과 엑셀 한 파일을 받을 수

## 알아 둘 점

- 끝장전은 사실상 9세트 고정입니다 (296경기 중 294경기가 9세트).
- ASL 기록에는 **경기 날짜가 없습니다**. 그래서 시간축이 아니라 대회·라운드 순서로만
  정리했습니다. 매치(시리즈)는 같은 라운드에서 같은 두 선수가 **연달아** 치른 세트를
  하나로 묶은 것이라, 조별 리그에서 같은 둘이 떨어져 두 번 만나면 별개 매치가 됩니다.
- ASL 맵 이름은 한글(이클립스, 서킷브레이커), 끝장전은 영문(Eclipse, Polypoid)으로
  시트에 적혀 있습니다. 원본 표기를 그대로 뒀습니다.
- **끝장전** 원본에는 세트마다 누가 이겼는지가 남아 있지 않고 합계만 있습니다.
  그래서 종족 상성은 "매치 스코어 + 두 선수의 종족" 으로 세트 단위까지 되살렸지만,
  맵별 승패를 연도별로 쪼개는 것은 불가능합니다. 반대로 **ASL** 원본은 세트마다
  승자가 남아 있어 맵별 승패가 정확합니다.
- 끝장전 2,656세트 가운데 36세트는 맵 이름이 비어 있어 맵 통계에서 빠집니다
  (그래서 맵 표의 합은 2,620세트입니다). ASL 은 2,177세트 전부 맵이 적혀 있습니다.
- 끝장전에는 동족전이 한 경기도 없습니다. ASL 은 549세트(T 245 · P 119 · Z 185)가
  동족전이라 종족 상성 막대에서 빠집니다 — 화면에도 그렇게 적어 두었습니다.
- ASL 시트에서 이영호가 9줄만 P·Z 로 적혀 있어(나머지 137줄은 T) 빌드할 때 최빈
  종족인 T 로 맞춥니다. 원본 엑셀은 건드리지 않으며, `tools/asl_import.py` 가
  이런 줄을 실행할 때마다 알려 줍니다.
